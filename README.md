# MainBoard Firmware — IMU & Spectral Data Logger

Firmware for a custom **STM32U575**-based mainboard designed as a wearable smart sensor platform.
The system acquires inertial and optical spectral data, stores them in NAND Flash memory, and streams them wirelessly over BLE or via USB — all while spending most of its time in ultra-low-power **Stop 2** sleep mode.



---

## Hardware Overview

| Component | Part | Interface |
|---|---|---|
| Microcontroller | STM32U575RIT | — |
| IMU | LSM6DSO16IS | I2C |
| Spectral Sensor | AS7341 (11-channel) | I2C |
| Flash Memory | Micron MT29F4G01 NAND (4 Gbit) | SPI3 |
| BLE Module | RN4871 | USART3 |
| USB | Full-Speed OTG (Virtual COM Port) | USB OTG FS |

## Key Features

### 1. Button-driven State Machine
The application logic is fully driven by a single **USER BUTTON** through four states defined in `Core/Inc/main.h`:

| State | Description |
|---|---|
| `STATE_IDLE` | Waiting for a button press or USB connection event |
| `STATE_ACQUISITION` | Autonomously sampling sensors; CPU sleeps in Stop 2 between cycles |
| `STATE_USB_CONNECTED` | USB enumerated; waiting for download command |
| `STATE_DOWNLOAD` | Streaming stored NAND data to the host over USB CDC |

### 2. IMU Driver 
`Core/Inc/imu_driver.h` · `Core/Src/imu_driver.c`

A lightweight driver for the **LSM6DSO16IS** 6-axis IMU:
- WHO_AM_I handshake on boot
- Configurable ODR (12.5 Hz → 208 Hz) and full-scale range for both accelerometer (±2 g to ±16 g) and gyroscope (250 dps → 2000 dps)
- Selectable High-Performance or Low-Power mode
- Raw + converted float output via `IMU_Data` struct
- Sampling triggered by TIM2 periodic interrupt

### 3. Spectral Sensor — AS7341 + Flicker Detection
`Core/Inc/Spec_AS7341.h` · `Core/Src/Spec_AS7341.c`

Driver for the **AS7341** 11-channel visible spectral sensor:
- SMUX (Sensor Multiplexer) routing configured at boot to map F1 (deep blue), F3 (blue), clear, and flicker channels onto the internal ADCs
- Flicker detection engine enabled concurrently with spectral acquisition (FDEN bit)
- Threshold interrupt configured via `SP_TH_H/L` registers: triggers an immediate BLE alert when an optical threshold is exceeded
- Hardware interrupt routed to `SP_INT_Pin (PB5)`, handled in `HAL_GPIO_EXTI_Falling_Callback`

### 4. LPBAM — Autonomous I2C Acquisition in Stop 2
`LPBAM/I2C_Spec/`

The most power-critical subsystem. A **Low-Power Background Autonomous Mode (LPBAM)** linked-list queue built with the STM32U5 LPBAM framework:

- **LPTIM1** generates a periodic PWM trigger that fires the LPDMA1 channel without waking the CPU
- The DMA autonomously re-issues I2C read transactions to the AS7341 (`0x93` STATUS → channel data) and deposits results directly into an SRAM4 retention buffer (`AS7341_Rx_Buffer[60]`)
- A separate flicker read populates `Flicker_buffer[5]`
- After 5 complete acquisition cycles, the DMA fires a transfer-complete callback that sets `lpbam_cycle_complete = 1` and wakes the CPU from Stop 2
- HSI is kept alive in Stop mode (`HSIKERON`) so the LPBAM subsystem can autonomously request it as needed

**LPBAM pipeline functions:**

| Function | File | Purpose |
|---|---|---|
| `MX_I2C_Spec_Init()` | `lpbam_i2c_spec_config.c` | Peripheral + queue base configuration |
| `MX_I2C_Spec_I2C_RX_Init()` | `lpbam_i2c_spec_i2c_rx_config.c` | Scenario-level I2C RX configuration |
| `MX_I2C_Spec_I2C_RX_Build()` | `lpbam_i2c_spec_i2c_rx_build.c` | Builds the DMA linked-list in SRAM4 |
| `MX_I2C_Spec_I2C_RX_Link()` | `lpbam_i2c_spec_i2c_rx_build.c` | Links the queue to LPDMA1 Channel 0 |
| `MX_I2C_Spec_I2C_RX_Start()` | `lpbam_i2c_spec_i2c_rx_build.c` | Starts autonomous DMA operation |

### 5. Data Processing — `Elabora_e_Salva_Campionamento()`
`Core/Src/callback_LPDMA.c`

On each CPU wake-up, raw bytes from SRAM4 are parsed and normalized:
1. **Gain extraction** from `ASTATUS[3:0]` using a LUT (0.5× → 512×)
2. **Flicker classification** — decodes 100 Hz / 120 Hz detection flags and validity bits; sets `pacchetto.luce_artificiale`
3. **Channel reconstruction** — little-endian 16-bit assembly of CH0 (deep blue), CH1 (blue), CH4 (clear)
4. **Gain normalization** — `channel_value × 1000 / actual_gain`, saturated to `uint16_t`
5. **NAND write** — packed into the `data_packet` structure and written to the next available NAND page

### 6. NAND Flash Storage 
`Core/Inc/SPI_NAND.h` · `Core/Src/SPI_NAND.c`  
`Core/Inc/Memory_operations.h` · `Core/Src/Memory_operations.c`

Full low-level NAND driver with:
- Block/page erase, program-load, program-execute, and cache-read command set
- Hardware ECC monitoring with status reporting (`ECC_STATUS_*` flags)
- **Bad-block management**: `find_bad_blocks()` scans all 2048 blocks at boot and maintains a bad-block table in SRAM4 retention memory
- **Circular wear-leveling**: the write pointer advances to the next good block each session
- **Session boundary tracking**: `session_start_block/page` and `session_end_block/page` kept in retention SRAM for crash-safe recovery
- `flush_nand_memory()` forces the last partial page to flash on a button-stop event to prevent data loss
- `read_memory_and_transmit()` streams all session data over USB CDC in `STATE_DOWNLOAD`

Storage layout: **292 samples per 4 KB page**, 14 bytes per sample.

### 7. Bluetooth Low Energy
`Core/Inc/bluetooth.h` · `Core/Src/bluetooth.c`

UART-based driver for the BLE module:
- Hard reset + initialization sequence at boot
- `BLE_SendData()` / `BLE_SendPacket()` for streaming typed data frames (IMU acceleration, gyroscope, spectral alerts)
- Dormant / wake-up / slow-advertisement modes for power management
- Threshold-crossing alerts sent immediately upon `as7341_int_alarm` interrupt

### 8. USB Virtual COM Port (VCP)
`Core/Inc/usb_otg.h`

Full-Speed USB OTG configured as a CDC (Communication Device Class) device:
- Detected via `usb_flag` set by the USB enumeration callback
- Triggers `STATE_USB_CONNECTED → STATE_DOWNLOAD` on button press
- Used to download stored NAND sessions to a host PC for post-processing

## Power Management

All retention variables are placed in **SRAM4** (`.sram4_retention` section), which is the only SRAM bank that retains content through Stop 2. This ensures the application state, NAND write pointers, bad-block table, and DMA buffers survive each low-power sleep cycle.

```
Stop 2 entry  →  LPTIM1 fires (autonomous)
     ↓              ↓
  CPU sleeps    LPDMA1 reads AS7341 via I2C
     ↓              ↓
  CPU wakes ← DMA transfer-complete IRQ
     ↓
  Process & store 5 samples → Stop 2 again
```

SysTick is suspended before entering Stop 2 to prevent 1 ms wake-ups. System clock (PLL from HSE) is reconfigured immediately after wake-up.

## Build & Flash

The project is developed in **STM32CubeIDE** and also supports **CMake** builds via the provided `CMakeLists.txt` and `CMakePresets.json`.

```bash
# CMake build (from repo root)
cmake --preset debug
cmake --build build/
```

Flash with STM32CubeProgrammer or the IDE's built-in J-Link/ST-Link runner.  
Debug `printf` output is routed to **ITM Stimulus Port 0** (SWO) for zero-cost trace logging.
